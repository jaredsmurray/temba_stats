Working with Codex

How to request, check, and save statistical analysis

Codex can prepare data, fit models, and create tables and plots. You still choose the method, check the output, and decide what the results mean.

Be precise

Name the data, variables, operation, and output you want. Specific requests give you an output that you can check against the prompt. If you do not know the variable names, ask Codex to list the names and types first.

Use this recipe:

Using [data or observations], use [variables] to [calculate, plot, or fit]. Return [the table, plot, model output, or saved result].

For example:

Using the housing data, keep observations with nonmissing PRICE and SQFT. Fit PRICE on SQFT and BATHS, treating ZIPCODE as categorical. Return the standardized regression table.

Keep each task focused

Use one task for one question or a closely related set of outputs. Ask for one meaningful analysis step, inspect the result, and then continue. This makes it easier to find the step where a problem entered.

Start a new task when you change questions or variables, or when repeated revisions stop helping. Saved output remains in the assignment folder, so tell the new task your current goal and the visible title of any output it should inspect.

Check before you build

Compare every output with your request before using it in the next step. Run one or two checks that could expose the mistake you are most worried about.

After filtering or changing data, you can ask Codex to:

  • Show the row count before and after the change.
  • Count missing values in the variables used.
  • Show the minimum and maximum of a new numeric variable.
  • Show category counts after recoding or grouping.

For a plot or table, check:

  • The observations and variables used.
  • The labels, units, axes, and category order.
  • Impossible values, unexpected categories, or empty groups.
  • Whether counts or percentages add to the expected total.

For a model, you can ask Codex to:

  • Show the exact formula it fit.
  • Report how many observations it used and excluded.
  • Confirm the reference group for a categorical variable.
  • Create the diagnostic plot required by the assignment.

If something looks wrong, name the mismatch and ask Codex to trace it. For example:

I expected about 300 observations, but this table uses 217. Show the row count after each filtering or missing-data step.

Ask for the right kind of help

Ask Codex to inspect data, diagnose errors, trace an operation, or check its work. These are mechanical questions that the harness can answer. If the remaining question is which method to choose, what a result means, or what conclusion to draw, use your course materials or ask your instructor. The harness leaves those decisions to you.

These prompts address common blocks:

  • If you do not know the variable names, ask: “List the variable names and types in the housing data.”
  • If the output may not match the request, ask: “Restate the exact variables, filter, and model used for ‘Housing price model,’ then check them against my request.”
  • If an output fails, ask: “Diagnose why this output did not render and fix the mechanical problem.”
  • If Codex refuses an allowed data operation, say: “I am asking for a data operation, not an interpretation. Identify the ambiguous wording and help me restate the same operation precisely.”

Save what you want to keep

Mark a finished output report ready and identify it by its visible title. This preserves the current version; it does not certify that the analysis is correct. Ask Codex for the clean R reproduction script when you want to inspect or reproduce the code.

For an important or complicated output, run a stronger independence check:

  1. Ask Codex for the clean R reproduction script.
  2. Give another local AI a fresh copy of the assignment folder and the script, without the original conversation.
  3. Ask it to describe the data, filters, transformations, variables, and analysis step by step.
  4. Ask it to run the script in a clean environment and compare the result with the saved output.
  5. Ask it to report errors, warnings, and differences without interpreting the results.

This check can expose a missing or inconsistent step. It is an imperfect substitute for reading the code because another AI can repeat the same mistake. Keep course data local unless your instructor allows you to share it with another service.

Before you finish

  • Does the output use the requested observations and variables?
  • Do the labels, units, and model formula match the request?
  • Did you run one useful check and resolve anything unexpected?
  • Did you mark the version you want to keep report ready?
